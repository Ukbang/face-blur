# 얼굴 자동 블러 웹앱 — 계획서

## Context
사진을 올리면 사람 얼굴을 자동으로 찾아 블러 처리해 주는 서비스를 만든다. 목적은 SNS나 블로그에 사진을 올릴 때 다른 사람의 초상권과 개인정보를 쉽게 보호하는 것이다.
`/Users/ukbang/Desktop/dev/blur_project`는 빈 폴더라 처음부터 만든다.

**사용자가 확정한 방향**
- 플랫폼: **웹앱**
- 처리 위치: **브라우저(기기) 안에서만 처리**. 사진은 서버로 전송하지 않는다.
- 스택: **React + Vite + TypeScript**, 정적 사이트로 배포
- MVP 기능: 자동 감지, 블러, 다운로드에 더해 **수동 수정**과 **블러 스타일 선택**

**계획 대비 바뀐 점**
- **정밀 감지 버튼(사용자 결정)**: 기본은 빠른 감지(약 1초)로 처리한다. 편집 화면의 "작은 얼굴 더 찾기" 버튼을 누를 때만 정밀 감지를 돌린다.
- **타일 크기를 이미지 크기에 맞춤**
  - 메신저 등으로 1600px까지 줄어든 단체 사진에서 감지가 29명 중 17명으로 떨어지는 문제를 발견했다.
  - 그래서 최소 타일 크기를 고정 480px에서 `max(240, 긴 변/8)`로 바꿨다. 정밀 감지는 `max(160, 긴 변/16)`이다.
  - 3840px 사진에서는 기존 값과 같다.
- **재확인(오탐 필터)은 끔**: 오탐은 줄지만 진짜 작은 얼굴도 크게 놓친다(Solvay 29→25). 놓친 얼굴이 오탐보다 위험하다고 판단했다.
- **디코딩**: `createImageBitmap(imageOrientation)` 대신 `<img>` 디코딩 후 canvas에 그린다. 브라우저 호환성 때문이고, EXIF 회전 반영과 메타데이터 제거는 그대로 된다.
- **블러 구현**: StackBlur 라이브러리 대신 얼굴을 칸 단위로 줄인 뒤 3패스 박스 블러를 직접 구현했다(의존성 없음).
- **박스 확장**: 상하좌우 25% 대신 좌우 20%, 위 35%(머리카락·이마), 아래 15%로 넓힌다.
- **테스트 이미지**: Unsplash 대신 Wikimedia Commons의 자유 라이선스 사진을 썼다. 출처는 `spike/images/SOURCES.md`에 있다.

## 구현 가능성 검토 — 결론: 가능
| 항목 | 판단 | 근거 / 대응 |
|---|---|---|
| 브라우저 얼굴 감지 | 가능 | MediaPipe Tasks Vision `FaceDetector`(BlazeFace)가 웹을 공식 지원한다. YuNet/SCRFD ONNX 모델은 onnxruntime-web으로 돌릴 수 있다. |
| 단체 사진의 작은 얼굴 | **주의** | BlazeFace의 입력은 128×128이다. 큰 사진을 그대로 넣으면 작은 얼굴을 놓친다. 이미지를 타일로 나눠 감지하고, 그래도 부족하면 YuNet으로 바꾼다(약 10px 얼굴까지 감지, 입력 크기 가변). |
| 감지 누락 | **불가피** | 옆얼굴, 가려진 얼굴, 아주 작은 얼굴은 어떤 모델도 놓칠 수 있다. 그래서 수동 추가와 해제 기능이 필수다. |
| 블러 복원 위험 | 대응 필요 | 약한 블러나 촘촘한 모자이크는 복원될 수 있다. 강도의 최솟값을 얼굴 크기에 비례해 강제한다. |
| 개인정보 | 유리 | 브라우저 안에서만 처리하므로 서버 저장과 처리방침 부담이 거의 없다. 모델과 WASM 파일도 직접 호스팅해 외부 요청을 없앤다. |
| EXIF(GPS 등) | 자동 해결 | 결과를 canvas에서 다시 인코딩하므로 메타데이터가 제거된다. 회전 정보만 업로드 시점에 먼저 반영한다. |
| 브라우저 호환 | 주의 | Safari의 `ctx.filter` 지원이 불안정해 쓰지 않는다. 블러는 직접 구현한다. iOS는 canvas 메모리 한도가 있어 아주 큰 이미지는 축소하고 안내한다. |

## 아키텍처
```
[업로드] → 디코딩(회전 보정, 크기 제한) → [감지 Worker] → 얼굴 박스(원본 픽셀 좌표)
                                                  ↓
                 [편집 화면: 박스 토글/추가/삭제/크기조절 + 스타일·강도]
                                                  ↓
                         효과 적용(미리보기: 화면 해상도 / 저장: 원본 해상도) → 다운로드
```
- 감지기는 인터페이스로 분리한다(`detect(image): FaceBox[]`). MediaPipe와 YuNet을 서로 바꿔 끼울 수 있게 한다.
- 얼굴 좌표는 항상 **원본 이미지 픽셀 기준**으로 저장한다. 화면 표시용 좌표는 따로 변환한다.
- 상태 관리는 `useReducer` 하나로 한다(faces, style, strength, image). 외부 상태 라이브러리는 쓰지 않는다.

## 단계별 작업

### Phase 0 — 세팅과 감지 모델 검증 (결정 지점)
- Vite React-TS 템플릿, ESLint, Vitest, Playwright를 세팅하고 `git init` 한다.
- 테스트 이미지 15~20장을 모은다. 라이선스가 자유로운 Unsplash 등에서 단체 사진, 멀리 있는 작은 얼굴, 옆얼굴, 마스크·선글라스, 어두운 사진을 고른다.
- MediaPipe BlazeFace로 감지율, 오탐, 처리 시간을 측정한다. 작은 얼굴을 놓치면 타일링을 적용해 다시 측정한다.
- **판단 기준**: 타일링까지 적용해도 단체 사진 감지율이 낮으면 YuNet(onnxruntime-web)으로 교체한다. 결과는 사용자에게 보고하고 진행한다.

### Phase 1 — 핵심 흐름 (업로드 → 감지 → 블러 → 다운로드)
- 드래그앤드롭과 파일 선택(JPEG/PNG/WebP)을 지원한다. `createImageBitmap(file, { imageOrientation: 'from-image' })`로 회전을 보정한다.
- 감지는 Web Worker에서 실행해 UI 멈춤을 막는다. Worker 호환이 어려우면 메인 스레드에서 실행하고 로딩 표시를 띄운다.
- 감지된 박스는 상하좌우 약 25% 여유를 두고 넓혀서 머리카락 경계와 귀까지 덮는다.
- 기본 효과는 강한 블러다. 원본 형식으로 원본 해상도 그대로 다운로드한다.

### Phase 2 — 수동 수정
- 박스를 클릭하면 블러가 켜지고 꺼진다. 꺼진 박스는 점선으로 표시한다.
- 빈 영역을 드래그하면 새 박스를 추가한다. 선택한 박스는 모서리 핸들로 크기 조절과 이동을 하고, Delete 키나 버튼으로 삭제한다.
- 마우스와 터치 모두 Pointer Events로 처리한다.

### Phase 3 — 블러 스타일과 강도
- 스타일은 4종이다. **가우시안 블러**는 강하게 축소한 뒤 StackBlur를 적용한다. **모자이크**는 축소 후 smoothing을 끄고 확대한다. **검정 박스**와 **이모지**도 지원한다.
- 마스크 모양은 사각형과 타원 중에서 고른다.
- 강도 슬라이더를 제공한다. 최솟값은 얼굴 크기에 비례해 강제한다. 예: 모자이크 블록 ≥ 얼굴 폭/8.
- 미리보기는 화면 해상도로 즉시 반영하고, 저장할 때만 원본 해상도로 다시 렌더링한다.

### Phase 4 — 완성도
- 모바일 반응형으로 만든다. 로딩, 에러, 얼굴 0개 상태별 안내를 넣는다.
- 아주 큰 이미지는 자동으로 축소하고 안내한다.
- "사진은 기기 밖으로 전송되지 않습니다" 안내 문구를 넣는다. CSP를 `connect-src 'self'`로 설정해 외부 전송을 원천 차단한다.

### Phase 5 — 배포
- Vercel에 정적 사이트로 배포한다. 배포 전에 사용자에게 확인을 받는다.

### MVP 이후 백로그
여러 장 일괄 처리와 ZIP 다운로드, HEIC(아이폰 사진) 지원, 동영상 블러, PWA 오프라인 지원, 모바일 앱.

## 검증 방법
- **단위 테스트 (Vitest)**
  - 좌표 변환(원본 ↔ 화면)을 확인한다.
  - 타일 병합과 NMS를 확인한다.
  - 효과를 적용했을 때 박스 안 픽셀은 바뀌고 박스 밖 픽셀은 그대로인지 확인한다.
- **E2E (Playwright)**
  - fixture 이미지를 업로드하면 박스가 N개 이상 나오는지 확인한다.
  - 토글과 추가 후 다운로드한 파일이 생성되고 크기가 원본과 같은지 확인한다.
  - **네트워크 요청에 이미지 업로드가 없는지** 확인한다.
- **수동 확인**: Chrome, Safari, iOS Safari, Android Chrome에서 Phase 0 테스트 이미지셋을 처리한다. 블러 결과를 확대해 얼굴을 알아볼 수 없는지 직접 본다.
- 실행: `npm run dev`, `npm test`, `npx playwright test`
