# Phase 0 — 얼굴 감지 모델 실험 결과

- 날짜: 2026-10-20
- 환경: MacBook, Chromium headless (Playwright), MediaPipe Tasks Vision 1.1.1 WASM (CPU)
- 테스트셋: Wikimedia Commons 자유 라이선스 사진 20장 (긴 변 최대 3840px). 출처는 `spike/images/SOURCES.md`
- 재현: `node scripts/fetch-spike-images.mjs && node scripts/spike-run.mjs`

## 결론
**MediaPipe BlazeFace full-range + 이미지 피라미드 타일링(최소 타일 480px)** 을 기본 감지기로 쓴다. YuNet 교체는 필요 없다.

- 사진 전체를 한 번에 넣는 방식은 단체 사진에서 거의 아무것도 못 찾는다. 모델 입력이 작기 때문이다(Solvay 0/29).
- 타일링을 적용하면 **Solvay 1927 단체 사진 29/29**를 찾고, Cornell 풋볼팀은 보이는 얼굴 거의 전부(55)를 찾는다.
- short-range 모델은 타일링을 하면 오탐(무대 조명 등)이 많고 단체 사진 감지율도 낮다.

## 관찰
1. **놓치는 경우**
   - 뒷모습과 고개 숙인 얼굴은 모델 특성상 원래 감지되지 않는다.
   - 약 10px 이하의 아주 작은 얼굴(1000명 이상 군중의 뒷줄)은 놓친다.
   - 마스크를 쓴 얼굴은 눈이 보이면 잡지만, 사진 가장자리에서 잘린 얼굴은 놓쳤다.
2. **오탐**
   - 점수 0.5~0.7 사이의 작은 박스가 옷 무늬, 헬멧, 거울 등에 생긴다.
   - 그런데 단체 사진의 진짜 작은 얼굴도 점수가 0.5~0.6이다. 임계값을 올리면 진짜 얼굴도 같이 사라진다.
3. **재확인(후보 주변을 잘라 다시 감지)**
   - 오탐은 확실히 줄어든다(jaipur 3→1, hongkong 3→1, buivien 5→2).
   - 하지만 작은 진짜 얼굴도 크게 잃는다(Solvay 29→25, Wikimania 106→53).
   - 프라이버시 도구에서는 **놓친 얼굴이 오탐보다 훨씬 나쁘다**. 그래서 기본은 끈다. 오탐은 편집 화면에서 클릭 한 번으로 해제한다.
   - 코드에는 `TilingOptions.verifyScore` 옵션으로 남겨둔다.
4. **240px 타일**: 군중 뒷줄 얼굴을 더 찾는다(WCI 103→133). 대신 처리 시간이 약 4배 늘어 데스크톱 기준 3~4.5초다.

## 앱 설계에 반영할 점
- 감지 결과는 모두 기본으로 블러 처리한다. 오탐은 사용자가 해제하고, 놓친 얼굴은 드래그로 추가한다. 수동 수정 기능의 중요성이 확인됐다.
- 감지는 3840px 사진 기준 데스크톱에서 약 1초, 모바일에서는 수 초가 걸릴 수 있다. Web Worker와 진행 표시가 필요하다.
- MediaPipe WASM은 약 13.5MB다. 첫 로딩 때 다운로드 표시가 필요하고, 이후에는 브라우저 캐시를 쓴다.
